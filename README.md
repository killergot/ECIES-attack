# ECIES invalid-curve attack

Учебный пример атаки на реализацию шифрования по схеме ECIES с кривой P-256. Сервер принимает зашифрованный файл и расшифровывает его, используя переданную в файле точку `R`. Репозиторий показывает, как отсутствие проверки этой точки позволяет восстановить секретный скаляр сервера через запросы к `/decrypt`.

## В чём проблема

В корректном обмене отправитель вычисляет `R = rP`, а получатель — общий секрет `K = dR`, где `P` — базовая точка, `d` — закрытый ключ. Точка `R` должна принадлежать ожидаемой кривой и допустимой подгруппе.

Здесь [`ECIES_decrypt`](src/logic_server.py) разбирает координаты из файла и сразу передаёт их в [`EllipticCurve.multiply`](src/curve_operation.py). Проверки принадлежности точки P-256 нет. Формулы сложения точек используют `p` и `a`, но не коэффициент `b`, поэтому ими можно умножать точки других кривых вида `y² = x³ + ax + bᵢ` над тем же полем.

Атакующий подставляет заранее выбранную точку `Rᵢ` малого порядка `lᵢ`. Тогда `dRᵢ` зависит только от `d mod lᵢ`. Для каждого кандидата вычисляется ключ HMAC и отправляется файл с соответствующей меткой. Ответ HTTP `200` означает, что кандидат прошёл проверку MAC. Повторив это для разных `lᵢ`, программа объединяет остатки китайской теоремой об остатках и проверяет полученный ключ по открытому ключу `Q = dP`. Поскольку KDF использует только координату `x`, точки `K` и `−K` неразличимы по MAC; программа перебирает оба знака остатка при проверке `Q`.

Это **атака на отсутствие валидации входной точки**, а не взлом математической задачи дискретного логарифма на P-256 или безопасной реализации ECIES. Демонстрационный сервер также хранит закрытый ключ прямо в исходном коде; он предназначен только для локального эксперимента.

## Установка

Нужны Python 3.9+ и `curl`. В корне репозитория создайте окружение и установите зависимости:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install aiohttp fastapi uvicorn python-multipart pycryptodome sympy
```

В проекте нет файла с зафиксированными версиями зависимостей. SageMath нужен только для отдельного скрипта в `experiments/`, не для сервера и атаки.

## Локальный запуск

Команды выполняются из корня репозитория. В одном терминале запустите сервер:

```bash
PYTHONPATH=src .venv/bin/python -m src.server
```

Сервер выведет координаты открытого ключа `Q` и начнёт слушать порт `8001`. Переменная `PYTHONPATH=src` нужна из-за импорта `curve_operation` в `src/logic_server.py`.

В другом терминале можно проверить обычное шифрование и расшифрование:

```bash
curl -fsS -F 'file=@examples/plaintext.txt' http://127.0.0.1:8001/encrypt -o encrypted.bin
curl -fsS -F 'file=@encrypted.bin' http://127.0.0.1:8001/decrypt -o decrypted.txt
cmp examples/plaintext.txt decrypted.txt
```

Затем запустите атаку, подставив **десятичные** координаты `Q`, напечатанные сервером:

```bash
.venv/bin/python main.py http://127.0.0.1:8001 <Q_x> <Q_y>
```

Вместо `<Q_x>` и `<Q_y>` нужны числа без угловых скобок. Программа отправляет много запросов к `/decrypt`, выводит промежуточные параметры и в конце строку `Восстановленный ключ: ...`. Для текущего демонстрационного сервера ожидаемый результат — `993913066640853197984481546239524653`. Запускайте опыт только против своего локального сервера или системы, которую вам разрешено тестировать.

## Как устроен пример

- [`src/server.py`](src/server.py) — HTTP API: `POST /encrypt` и `POST /decrypt`, оба принимают файл в поле формы `file`.
- [`src/logic_server.py`](src/logic_server.py) — демонстрационные шифрование и расшифрование: общий секрет из точки, SHA-512 для двух ключей, AES-CTR и HMAC-SHA256.
- [`main.py`](main.py) — клиент атаки: подбор остатков закрытого ключа по ответам сервера, CRT и сверка с `Q`.
- [`src/consts.py`](src/consts.py) — заранее подготовленные параметры точек на вспомогательных кривых.
- [`experiments/`](experiments/) и [`examples/legacy/`](examples/legacy/) — исследовательские заготовки и старые артефакты; для воспроизведения атаки они не нужны.

Формат зашифрованного файла: `0x04 || x(R)[32] || y(R)[32] || HMAC-SHA256[32] || nonce[8] || AES-CTR(ciphertext)`. Числа в квадратных скобках — длины в байтах. Сервер считает общим секретом `dR` и выводит из десятичной строки `x(dR)` ключи шифрования и MAC.

## Ограничения и исправление

Активный набор параметров рассчитан на демонстрационный ключ: для другого ключа успешное восстановление не гарантировано. Клиент считает успехом только HTTP `200`; ошибки и тайм-ауты он трактует как неудачный кандидат. Сервер при ошибке MAC сейчас возвращает `500` из-за общего обработчика исключений, хотя внутри предусмотрен `400`; на этот конкретный код ответа атака не опирается.

Для устранения показанной уязвимости перед умножением на `d` следует проверять кодировку точки, диапазон координат, принадлежность именно выбранной кривой, допустимость точки и её порядок. В реальном приложении лучше использовать проверенную криптографическую библиотеку и стандартизованный вариант ECIES/KEM вместо этого учебного кода.
